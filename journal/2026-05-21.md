## UEFN dashboard UI/UX pass

Intelligence dashboard. Did a focused CSS/JSX pass on
[UefnDemandDashboard](../path-builder/src/components/UefnDemandDashboard/).

  flips tooltips below the trigger).
- `.suggestion-metrics`: `align-items: baseline` → `center`, plus
  `flex-wrap: wrap` so confidence/decay/trends/SEO badges align with the
  numeric metrics instead of floating off the baseline.
- `.suggestion-meta-row`: baseline → center so platform dots line up with the
  category text.
- Removed pixel hacks (`margin-top: 1px` on rank, `top: 1px` on platform dot).
- `.column-header`: dropped the `min-height: 125px` hack, split into
  `column-header-top` + filters rows so the heading + Blue Ocean toggle sit
  cleanly on one row.
- Moved Blue Ocean toggle's inline styles into `.blue-ocean-toggle` CSS.
- Consolidated duplicate `max-width` on the dashboard root, cleaned dup
  margins on `.granular-coverage`, purged stale `!important` overrides on
  `.stats-bar`, `.provenance-footer`, `.industry-filter-row`.
- Replaced fixed `width: 60% / 40%` column widths with `flex: 3 1 0 / 2 1 0`
  and `min-width: 0` so flex math drives sizing.

## Demand dashboard source links → real pages

Sam reported source links on the demand dashboard "do not open real web pages."
Investigation traced the bug to [scripts/scrape-demand-intel.js](../scripts/scrape-demand-intel.js):
the trending-questions and pain-points scrape prompts both demanded a URL on
every source, which pressured Gemini to fabricate plausible-looking links
that 404'd. Even with `tools: [{google_search: {}}]` enabled, URLs inlined in
the JSON response were not constrained to the URIs grounding actually browsed
— those live in `groundingMetadata.groundingChunks[].web.uri` and were
captured but never used.

Two-step fix landed across commits `22561e0c → 3f9effea`:

1. **Dashboard fallback** ([UefnDemandDashboard.jsx](../path-builder/src/components/UefnDemandDashboard/UefnDemandDashboard.jsx)
   `getFallbackUrl`): only trust `source.url` when `source.verified` is set.
   Unflagged URLs route through platform-specific search URLs (Reddit search,
   YouTube search, Epic forum search, site-scoped Google for dev.epicgames.com)
   that always resolve. Fixes existing scraped data immediately, no re-scrape.

2. **Scraper grounding** ([scripts/scrape-demand-intel.js](../scripts/scrape-demand-intel.js)):
   capture `groundingMetadata.groundingChunks` from each Gemini call, match
   each LLM-emitted source by title (`findGroundedUri`, with title
   normalization that strips trailing " - hostname.com"), and substitute the
   chunk's verified `web.uri` (a `vertexaisearch.cloud.google.com/grounding-api-redirect/…`
   URL that follows to the real source for ~30 days). Sources carry a
   `verified` boolean so the dashboard knows which to trust.

### Two-pass scrape

First post-fix scrape run showed `groundingChunks` emitted for only ~10% of
calls (UEFN run `26232975944` debug log). Cause: when Gemini is asked for
structured JSON, it skips the prose space where citations attach, so the
grounding system has nothing to thread URIs to. Switched both scrape paths
to two-pass:

- **Pass 1** (grounded): freeform prose research summary with explicit
  "from a Reddit thread titled X" citations. Numbered list format with
  explicit yield enforcement ("you MUST produce exactly N entries").
- **Pass 2** (no grounding, JSON mode): plain shaping over pass-1 prose.

Pass-1 chunks carry forward to the normalize step, which calls
`findGroundedUri` to swap each LLM URL for a verified one.

Also dropped `callGemini`'s "grounded empty text → retry without grounding"
fallback: that quietly stripped chunks from pass 1 when it should fail loudly
so the caller can skip.

## CI - Tests was silently red for 12+ pushes

Discovered while verifying the demand-intel deploy: every push to master since
2026-05-19 had a failing `CI - Tests` run nobody noticed. Pages-deploy is a
separate workflow that stayed green throughout, so the live site shipped fine
— but real test signal was dark.

Two stale tests caused all the noise:

- `path-builder/e2e/tab-navigation.spec.js` + `search-flow.spec.js` filtered
  the sidebar tab on `/Fix a Problem/` / `/Learn Why/`. The tab was renamed
  to "Tutor" in commit `24fd6e21` (tutor pivot, 2026-04-22) and the specs
  weren't updated. Also `ProblemFirst` swapped its primary composer to
  `ChatInput` (`aria-label="Chat input"`, "Send" button) — the legacy
  `ProblemInput` ("Problem description" / "Get Diagnosis") still exists but
  is nested in a collapsed `<details>` for attachments, so it's hidden on
  tab load. Updated both specs to drive the new composer.
- `tests/tags_validate.test.js` read `sample_data/tags.json`, a file
  intentionally deleted in `83c8a2f8` (2026-04-29 "chore: remove tracked
  sample_data backup"). Test wasn't pruned. Removed the stale case; the
  `tags/tags.json` validation case still runs.

Commits: `b4a8c433`, `341189f7`, `bff0021c`. Green at run `26236210750`.

### Hardening so this doesn't recur

User picked the most rigorous option: switch to a PR-only workflow + branch
protection on master, with auto-issue notifications as a safety net.

- Added [.github/workflows/notify-ci-failure.yml](../.github/workflows/notify-ci-failure.yml):
  triggers on `workflow_run` for `CI - Tests` completing on master. On
  failure, opens (or comments on the existing) `ci-failure`-labeled issue
  with the run URL, commit SHA, and author. On success, closes any open
  ones. Filters to `event == 'push'` so PR-triggered runs (already visible
  in the PR checks UI) don't spam issues.
- Enabled branch protection on master via `gh api`: require status checks
  (`coverage`, `test`, `validate-schemas`, `functions-quality`,
  `path-builder-quality`, `tag-quality`) to pass, require branches up to
  date before merging, block direct pushes, block force pushes.

The auto-issue workflow is the catch-net for E2E breakages (which only
manifest in CI), and the PR/status-check requirement prevents the kind of
landings that broke things in the first place.
