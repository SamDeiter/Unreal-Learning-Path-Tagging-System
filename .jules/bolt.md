## 2025-05-12 - TagGraphService scoring bottleneck
**Learning:** `TagGraphService.scoreCourseRelevance` is a hot path used for matching courses to user queries. In its current implementation, it performs a full BFS graph traversal (up to 2 hops) for every query tag *for every course* being scored. It also redundantly normalizes course tags and performs suffix matching in a loop. For a library of ~2,400 courses, this results in significant overhead.
**Action:** Implement identity-based caching for course metadata using `WeakMap` and BFS expansion caching using `Map`. This will reduce the complexity of batch scoring from $O(C \times T \times BFS)$ to $O(C \times T)$ for course-level matching and $O(T \times BFS)$ for graph-level expansion, where $C$ is the number of courses and $T$ is the number of query tags.
