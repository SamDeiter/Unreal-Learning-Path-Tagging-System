## 2026-05-21 - Semantic Deduplication Optimization
**Learning:** For quadratic-style comparison loops (like $O(N^2)$ Jaccard similarity checks across retrieved passages), tokenizing texts and allocating new `Set` or `Array` structures inside the comparison inner loop causes immense CPU and memory allocation overhead. Instead, pre-calculating the Sets once in an $O(N)$ pass, using a local `Map` to cache them, and computing Jaccard similarity via the Inclusion-Exclusion Principle ($|A \cup B| = |A| + |B| - |A \cap B|$) avoids any allocation or string parsing during comparison, yielding a massive performance speedup.
**Action:** Always pre-calculate parsed states and data structures before entering nested loops, and use mathematically optimal, zero-allocation intersection-exclusion checks when computing similarity statistics.
