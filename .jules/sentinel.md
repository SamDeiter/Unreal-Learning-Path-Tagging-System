## 2026-05-22 - Firestore Subcollection Non-Inheritance and Root-Level BOLA/IDOR
**Vulnerability:** A Broken Object Level Authorization (BOLA) and Insecure Direct Object Reference (IDOR) existed in Firestore security rules. There was an insecure root-level `/token_usage/{dateKey}` rule block allowing any authenticated user to read/write any other user's daily usage stats. Meanwhile, the actual frontend code migrated to the user-isolated subcollection path `/users/{uid}/token_usage/{dateKey}`, but no specific security rules were defined for this subcollection under the parent `match /users/{uid}` block.
**Learning:** Firestore security rules do not automatically cascade or inherit access control configurations from a parent document rule down to its subcollections. If a subcollection is not explicitly defined with a matching block, it falls back to the default deny-all rule, while legacy/duplicate root-level match rules can leave wide security gaps.
**Prevention:** Always explicitly define nested match blocks for subcollections in `firestore.rules` even if the parent document has strict permissions. Additionally, routinely audit and clean up legacy or unused root-level matches when migrating data to user-isolated nested paths.
