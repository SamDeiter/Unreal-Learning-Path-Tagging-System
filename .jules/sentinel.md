## 2026-05-21 - BOLA/IDOR in Firestore Token Usage Collection
**Vulnerability:** The client-side cost/token usage tracking data was written to and read from a global, root-level `token_usage` collection with an insecure Firestore rule allowing any authenticated user to read and write records. Any user could enumerate or corrupt other users' usage statistics.
**Learning:** Root-level collections without per-user document keys are inherently vulnerable to BOLA/IDOR because there is no identifier in the path to restrict access to only the owning user. Standard authentication checks (`request.auth != null`) do not enforce authorization boundaries.
**Prevention:** Nest user-specific or client-tracked stats subcollections securely under the user's document path (e.g. `/users/{uid}/token_usage/{dateKey}`) where the parent `uid` is securely checked against `request.auth.uid`. Ensure that Firestore rules explicitly matches subcollections and validates authorization, and that client-side helpers resolve and scope paths using the current user's UID.
