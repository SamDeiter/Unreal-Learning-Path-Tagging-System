## 2026-05-21 - BOLA/IDOR Vulnerability in Token Tracker Client Sync
**Vulnerability:** The client-side token tracking sync system loaded daily stats using a root-level document query (`token_usage/{date}`) in Firestore. Because access controls only verified authentication (`request.auth != null`), any logged-in user could read or overwrite any other user's daily API token usage metrics, leading to Broken Object Level Authorization (BOLA) and Insecure Direct Object References (IDOR).
**Learning:** The initial implementation relied on global dates as document IDs under a root collection to log token statistics, assuming token tracking was purely an administrative read. However, when writing to this collection from the client SDK, the lack of user scoping allowed multi-tenant data collisions and unauthorized data extraction.
**Prevention:** Always scope user-specific statistics and tracking logs to subcollections nested under the user's document (`users/{uid}/token_usage/{date}`) and enforce matching ownership checks (`request.auth.uid == uid`) in Firestore Security Rules.
