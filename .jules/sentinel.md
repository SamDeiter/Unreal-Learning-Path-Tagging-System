## 2026-03-03 - [Vulnerability] Atomic Increments and Data Visibility
**Vulnerability:** The `path_builder_invites` collection allowed `usedCount` to be updated by any authenticated user without enforcing atomic increments or server-side timestamp validation. Additionally, sensitive collections like `analytics_events` and `token_usage` were readable by all authenticated users, potentially exposing usage patterns and cost data.
**Learning:** Firestore security rules must explicitly validate that increments are atomic (e.g., `request.resource.data.usedCount == resource.data.usedCount + 1`) to prevent users from accidentally or maliciously skipping or resetting usage counts. Sensitive metadata and analytics should always be restricted to administrators via `isAdmin()` or similar role-based checks.
**Prevention:** Always use `request.time` for server-side timestamp validation and enforce specific field deltas for numeric increments in Firestore rules. Implement strict role-based access control (RBAC) for all collections containing non-public data.
