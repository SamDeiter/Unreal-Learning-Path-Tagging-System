## 2026-05-21 - [BOLA/IDOR in Token Usage Collection]
**Vulnerability:** A Broken Object Level Authorization (BOLA) / Insecure Direct Object Reference (IDOR) vulnerability existed in the `/token_usage` Firestore collection. Since `/token_usage` was a global root collection and its security rules only checked `request.auth != null`, any authenticated user could query or overwrite any other user's daily token stats.
**Learning:** Storing telemetry or operational data (like token usage) in global collections without checking if the specific document's owner matches the requester's ID results in severe direct object reference vulnerabilities, even when user-specific structures are intended. Nesting these documents under user-scoped paths (`/users/{uid}/token_usage/{dateKey}`) is a robust, clean security pattern to guarantee authorization isolation natively in Firestore rules using parent-scope match variables.
**Prevention:** Avoid root-level global collections for per-user data unless strict field-level ownership checks (e.g. `resource.data.userId == request.auth.uid`) are performed on all operations. Prefer user-scoped subcollections where Firestore match parameters can enforce proper isolation natively.
