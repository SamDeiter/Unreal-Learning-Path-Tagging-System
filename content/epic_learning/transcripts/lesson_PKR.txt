In this video, we'll take a little step back from our project and walk through everything we've learned about Paper 2D. We will summarize what we've built, how it works and how Paper 2D helped us to get there. We began by creating a brand new Paper 2D based project and included the start of content. We opened the project and took a quick tour of the key features of the start of project, including the Paper 2D based assets. From there, we moved quickly on to importing our own source assets, and we saw how Paper 2D helped us pick the optimal settings during the import process. Once the assets were imported, we got to work, turning them into something we could use in our game. We took the character images and turned them into animated sprites, called flipbooks. We took our tile sheet and turned it into a tile set. We then configured the tile set and used the tile set to create a tile map. We then created a new level file and added our tile maps into it. Then we moved on to the most important part of the course, creating a fully functional player character. We started by reviewing the components that make up a character in Unreal Engine and compared this to a typical 3D character. We then went ahead and created a new character from scratch, starting with basic left and right movement. Once the character was moving around, we added Blueprint Logic to check for this movement and update the idle and walk animations at the correct time. We then built upon this foundation to extend our character's range of movement. We added the ability for the player to jump and refined our flipbook control logic in the event graph to handle the multi stage non looping jump animations alongside our looping, run, and walk animations. We finished up by adding a new input for running and added a configurable running speed to our character. With our sidescrolling 2D character in a good place, we turned our attention to the possibility of creating a 2D game from a top down perspective. We duplicated our sidescrawler character and started modifying the sprite and camera components to be viewed from a top down perspective. We then changed the rotation of these key components to be absolute rotations rather than relative to the character. This allowed us to independently rotate the character sprite component and the character controller in the event graph, so that the character could be moving in one direction without the sprite having to match this rotation. We then finished up by building a very simple prototype level which we used to test our new top down character in a play in editor session. In this video, we summarized everything we've learned during the course. We saw how Paper 2D empowers us to create 2D games by providing tools to import source assets, create animations we can use for characters and create tile-based levels using built-in editors. We also saw how these tools don't limit us to a sidescrawler perspective. We can easily modify our character to work from a top down perspective and apply the same logic to work from all manner of popular 2D perspectives.
