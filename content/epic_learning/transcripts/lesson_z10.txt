Deploying from Windows to Windows is probably the most straightforward way to deploy your project from UE4. Modern gaming PCs generally have plenty of RAM, video hardware, and support most everything UE4 offers in terms of features. If your game runs in the play menu, chances are it will package successfully. To deploy from Windows, let's begin by launching the editor, and once open, select New Project, Blueprint, and First Person Shooter. Let's make sure that the target hardware is selected as Desktop Console, we set the maximum quality, and don't include starter content since we won't be needing it. Now select a location for the project to live and name the project. Once all that is done, hit Create Project. Now that the editor is open, let's give the project a quick test by dropping down the Play button and selecting Standalone Game. This will launch the project and effectively package it for a quick test. This is generally the way you will want to test your project before deploying. If it has trouble here, you will know it likely won't build. As you can see, my project plays successfully, and I am ready to deploy. Press the Tilt-A key on your keyboard and type Quick Game to exit. Since everything worked in our test, let's go ahead and package this project for Windows. To do so, click on File and drag down to Package Project. Then Windows, and finally Windows X64 or X86, dependent on your hardware. Virtually all modern PCs are X64, so unless you're using a very old computer, you probably will also want to select X64. Now we will need to select where we want the package to be created. It will default to the project folder. For ease of finding, I'm going to go ahead and use my Desktop instead and create a folder called FPS Shooter Example. All we have to do is click Select Folder, and at this point, the project should begin building. If you open your output log, you will see all packaging steps being listed. This window will become a close friend to you as it will give insightful clues should builds fail and generally points you to the problem. With some luck, the packaging will complete with build successful printed at the bottom of the log. Now, all that's left to do is to test the package project. Let's jump over to our Desktop and open the folder we created. The first thing you will notice is that our project lives inside of a folder called Windows No Editor. This is standard and normal. You can of course change the folder name. Just be aware that when you repackage, it will recreate the folder again, giving you a second build and not an overwritten one. Within this folder, we are going to find your EXE file. This is what you will double-click to launch your project without the assistance of the editor. Let's go ahead and try that now. Since everything seems to be working, let's hit Till Day and type Quick Game to Exit the Game. Your project is now ready for distribution. Note however, this EXE file must live with the other files and folders found within the Windows No Editor folder. Since the name Windows No Editor is rather lackluster and is a poor description of our project, let's rename it to something more meaningful and zip up our project so we can easily send it to whomever we want. By doing it this way, you ensure all files stay together and that your project plays as expected wherever it is sent.
