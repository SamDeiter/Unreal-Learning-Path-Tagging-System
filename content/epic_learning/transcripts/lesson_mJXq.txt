In this video, we'll wrap up our exploration of the damage system by creating one more actor, an environmental hazard that will damage the player if they collide with it. We'll start by making a new blueprint actor for the hazard. Navigate to content 2D side scroller BP Blueprints. Right-click in the content browser and select New Folder. Name this new folder, Environment, and then Open the folder. Right-click in an empty space within the content browser and select Blueprint class to add a new blueprint. Select the actor type and name the new blueprint damage area. Double-click on the blueprint to open it in the Blueprint Editor. We'll start by setting up the components we need. From the Components panel, select Add Component and add a Box Collision component, leaving the default name of Box. Drag the Box Collision over the scene route in the hierarchy to make the collision the new root object. With the Box still selected, add a Paper Flipbook component. Once again, the default name of Paper Flipbook is perfectly fine, so press Enter. With the Paper Flipbook still selected, move over to the Details panel on the right-hand side and locate the sprite rollout. For the source flipbook, select Flipbook underscore FloorSpark. Select the viewport to the right angle and a lighting mode to unlit. Select the flipbook and position it roughly in the centre of the collision box. It doesn't have to be perfect. Select the collision box and change the Box Extend to 15, 15, 15 for X, Y and Z. Once again, don't worry about matching up the collision perfectly, we can always come back and adjust it later, and to be honest, visuals rarely match up exactly with collision volumes anyway. Next, add a float variable called Damage Amount. Compile the Blueprint so that we can set a default value. Set the default Damage Amount to 25. Now, let's head over to the Event Graph to implement the logic for when an actor overlaps the collision component of this Blueprint. Delete all the nodes apart from actor begin overlap. Drag from the event and locate Apply Damage. Connect the other actor output to the Damage Actor input on the Apply Damage function. Drag from the base damage input on the Apply Damage function and locate our Damage Amount variable. Drag from the Damage CAUSER input and locate Get a Reference to Self. Finally, for the Damage Type class, select DMG Type BP underscore environmental from the drop down. The cool thing about this is, our existing not-back logic will work with this interaction, just like it did for the projectile. This is because the not-back response occurs as part of the player characters response to any damage. The not-back function will also calculate the right direction to launch the player based upon the position of both actors, so we don't have to repeat any of that logic here again either. Nice. With that in mind, compile, save and close the Blueprint Editor window. Let's move our Healing Object for now and place a Damage Area Actor in a similar place. Start a plane editor session and walk into the Damage Area. Note how we received damage and are not-back in the opposite direction. And with that, we're done with the Damage Area. This was much easier to implement because it built on top of systems we've already designed and implemented. We can now end the plane editor session and look towards improving the fundamentals of our existing level.
