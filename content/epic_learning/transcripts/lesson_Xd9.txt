So the aim of this module is to get you comfortable with the thorny question of when you should use actors versus components for a particular piece of functionality. Now it mostly comes down to what the two of them are able to do and they are designed for very different purposes. So it makes sense that this comparison looks quite different. The idea of an actor is that they are easily placed within levels and compose of multiple components to get their job done. Now they can have some functionality of their own, but mostly their functionality comes from the components. Now there are a few commonalities between the two such as both of them can inherit so an actor can inherit from another actor. We can also have a component inherit from another component as we've seen we are able to inherit from the scene component, which gives us a bunch of functionality. Also if you derive them in blue prints and use the blueprint subclass you can override some of the default values and you can have your game designers responsible for setting up those default values so that works in both cases. However, between the two the maintainability and modularity is quite different. If you write a lot of code into actors, then you aren't going to be able to reuse that as readily as if you had written into components. And also because you tend to compose actors out of lots of small components, it means that the maintainability of the components is much higher because each component is just having a single responsibility. Whereas by their very nature, actors tend to be across the board doing things from sound to AI. And so if you write code that's specific to actors, that code's not going to be reused and also it's going to go and span across multiple different disciplines. So the final note here is about compose ability now actors can be composed within other actors. However, you would only want to do this rarely because the way the editor is set up and the way that the gameplay framework is set up. This isn't the easiest thing in the world to do and it's much more set up for components to be composed within actors. Similarly, components can be very well composed within actors. However, you cannot easily compose a component within another component. Again, that's slightly harder.
