Unreal Build Tool es el compilador multiplataforma de UE y está escrito en C#. El código fuente del motor está disponible para que veas cómo lo actualizamos. Incluso puedes modificarlo. Por eso, cada archivo fuente con código C++ reside en un módulo. Un módulo es un conjunto de clases con un único archivo de versiones en C++ que dicta cómo deben compilarse. Unreal Engine se compone de más de mil módulos. Cada módulo se compila en su archivo DLL para el editor y los proyectos de empaquetado los combinan en un ejecutable. Eso es el compilado monolítico. Al crear un proyecto, se creará un módulo por defect en el que poner el código. Recomendamos crear módulos adicionales según necesites para que el código sea modular y reutilizable. Un complemento es un conjunto de módulos o recursos. Al llevar un módulo a un complemento, es más fácil compartir el código entre proyectos distintos e incluso empaquetarlos para compartirlos o venderlos en Marketplace. El complemento "Game Features" es un tipo especial para activar funciones en ejecución. Y el código de una plataforma concreta puede aislarse con "Platform Extensions". Las macros son el modo principal de integrar el código de C++ con Unreal Engine y de mostrar las funciones en el editor. Proporcionan metadatos y funciones para los blueprints, las redes, los reflejos, la serialización y otros sistemas. "UCLASS", "USTRUCT" y "UENUM" se usan para mostrar tipos en Unreal Engine y son compatibles con Blueprint y el editor. "UPROPERTY" muestra los miembros de las clases en Unreal Engine para Blueprint y el panel "Details". Puede determinarse dónde se verá, accederá y editará la propiedad. Por último, "UFUNCTION" muestra funciones en Unreal Engine. Estos son los pilares de Unreal Engine. UE tiene su propia biblioteca estándar, No hace falta usar la biblioteca estándar de C++. Para los números enteros, en cambio, hay "ints" y "uints" de tamaño concreto. Los tamaños de los enteros simples varían entre plataformas. Pueden usarse enteros simples si la variable no se ha serializado, como con los bucles "for", pero siempre es preferible usar los de tamaño explícito. UE tiene varios tipos de cadenas para varias necesidades. "FString" es una cadena simple estándar. Engloba una amplia matriz de personajes y es mutable. "FName" aplica "hash" y hace caché de las cadenas en un mapa global al que se referencia con variables "FName". Al almacenar el índice de la cadena, pueden hacerse comparaciones muy rápido. También hay un índice al final que puede aumentar sin crear cadenas nuevas. Distinguen mayúsculas y minúsculas, y son más útiles para nombres y rutas. "FText" son cadenas con compatibilidad integrada con localización. Las recoge el sistema de localización del motor para traducir desde una sola fuente. Se usan para los textos que lean los usuarios. UE tiene los tipos estándar de recolección de cualquier lenguaje de programación, como las matrices, los mapas y los conjuntos. Hay muestras, pueden mostrarse en Blueprint y son compatibles con la replicación y las asignaciones de memoria, como la segura, la dinámica y la que se inserta en código. Un actor es todo lo que pueda añadirse al nivel. Las clases deberían prefijarse con "A". Los actores se cargan y destruyen con su nivel padre automáticamente. Puedes asignar actores nuevos dinámicamente con la función "Spawn Actor" y destruirlos con la función "Destroy". Además de crear un nuevo tipo de actor, también puedes añadirle funciones con los componentes. Contienen la representación real de lo que se añade en el nivel. El actor padre es sobre todo un contenedor. Un componente puede ser un componente "UActor" sin representación en el mundo o un componente "UScene", que tiene una transformación relativa al actor padre. Los actores pueden tener componentes de esos tipos y un componente de rutina en el que se basan las transformaciones. Los componentes valen para añadir conjuntos de funciones a actores sin tener que modificar su jerarquía de herencia. Los actores pueden eliminarse de un nivel con "Destroy", pero el recolector de basura será lo que libere memoria. No debe gestionarse la vida útil con palabras clave como "New", "Delete" o "Smart Pointers". Un error muy común que se comete con "UObjects" es el tener punteros sin la macro "UProperty". No son visibles para el recolector, por lo que el objeto puede recogerse y el puntero apunta a datos inválidos y difíciles de depurar. Hay dos punteros inteligentes en Unreal Engine. El trazado con "UObject" está a la izquierda y el sin "UObject" está a la derecha. Es importante no usar los punteros de la derecha en ningún "UObject". Los elementos se cargan en un mapa o podemos cargar un objeto desde una referencia blanda. El recolector de basura descarga los objetos cuando ya nada les hace referencia. UE tiene una base sólida que puede usarse para la mayoría de tipos de juegos, llamada "marco de mecánicas". Es compatible con el modo multijugador de forma nativa. El modo de juego es el objeto de un nivel que define las reglas para dicho nivel, como qué peones se generarán, la clase de HUD, etc. Al crear un proyecto nuevo, lo primero es crear el modo de juego a sobrescribir. Para el modo multijugador, esta instancia de objeto solo existe en el servidor. Define las reglas de la sesión, quién se une, las normas de los espectadores, etc. No sobrevivirá a una transición de alto nivel, así que no vale para guardar datos persistentes. Para ello, puede usarse la instancia del juego. Cada cliente tiene una instancia de juego que persiste a lo largo de su vida útil. Es una instancia global accesible desde todas partes. Puede ampliarse para el proyecto o crear un subsistema de la instancia del juego, que es como un componente para la instancia del juego. El estado del juego es un objeto que se replica del servidor a todos los clientes. Si el modo de juego muestra los puntos máximos del equipo para ganar, el estado del juego se usa para contabilizar los puntos actuales y tiene una lista de los estados de los jugadores. El estado del jugador es la información específica de un jugador. Se replica del servidor a todos los clientes y almacena el nombre, la puntuación y el ping del jugador.
