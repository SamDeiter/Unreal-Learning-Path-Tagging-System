By using various optimization view modes in the Unreal Engine viewport, we can visually see what, if anything, might need to be modified to improve performance. In this module, we'll look at the light complexity, shader complexity, and quad-overdraw view modes. By default, the viewport is set to show a lit rendering of our scene with post-process effects and dynamic lighting. By selecting the lit view mode icon, we can select various view modes that are used just for optimization. Go down to optimization view modes and choose light complexity. This shows our scene with a gradient of colors from green for low complexity to bright red and white for high complexity. I brought these point lights back into the scene so we can see how they affect performance. Previously, we determined that they are severely impacting the GPU performance in the project. Now we can see why. Where the light attenuation for dynamic lights overlaps, the complexity is much higher. Static lights that are baked into the scene have a very low cost and could be used here if the geometry is also going to be static. Again, these lights could just be deleted to bring the complexity down to a manageable level. Or we could just adjust the attenuation radius of the dynamic lights so they are no longer overlapping. Let's look at shader complexity. When you select this view mode, you may need to wait a few moments of shader's compile. This view mode is used to visualize the amount of shader instructions that are being used to calculate each pixel of the scene at a given point. Light green areas are ideal and inexpensive and red and white are very expensive. It looks like, for the most part, this motorcycle isn't using any shaders that are using too many instructions. If your viewport is covered in red and white areas, you may want to consider finding a way to minimize the instruction count in the materials used for those areas. If you're working in a model that could contain multiple layers of transparency, like an architecture model with windows on multiple sides of a room, you could see performance loss at times that the viewport faces through those several layers. If that is an issue in your project, consider modifying the glass material that you're using to be less expensive. Lastly, let's look at the quad-overdraw debug view mode. Here, we can visualize areas where geometry appears to be too dense. When multiple triangles are being rendered on the same pixel, those pixels have to be rendered multiple times. This can have a significant impact on performance. Because higher polygeometry has more overdraw, lower polygeometry is typically much easier to render. To reduce overdraw, consider using a distance-calling volume to make objects hidden when they are further away from the camera, or consider using LODs or levels of detail for your higher polygeometry. We'll learn more about LODs and how to create them later in this course.
