The prospect of adopting containers for your own Unreal Engine project can be quite daunting at first, but for most scenarios it's actually quite straightforward. To demonstrate how simple it is to adopt containers for building dedicated servers, we'll apply the code from the previous example to a new project. Here we have the Hour of Code sample project from the Unreal Engine marketplace. The project has been modified to support using a dedicated server, but no other changes have been made yet to support containers. First, we'll simply copy over the Dockerfile and Docker Ignore file from the previous example. Now the files have been copied, all we need to do is modify the Dockerfile to work with this project. The Dockerfile contains multiple references to the name of the project, which currently read third person demo. All we need to do is replace all occurrences of this name with the name of the new Unreal Engine project, which is Unreal Engine Hour of Code. With the Dockerfile updated for the new project, we can build and run our dedicated server using the exact same commands before. I've changed the name of the container image here, but you could just as easily use the old name and overwrite the existing container image from the previous project. With the dedicated server now built and running, we can run multiple instances of the new project and connect to the shared game session. As you can see, adopting containers for building your project's dedicated server is a simple process that can be rapidly repeated for new projects.
