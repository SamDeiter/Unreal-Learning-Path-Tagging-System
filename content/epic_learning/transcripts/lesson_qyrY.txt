A key aspect of being able to light a visualization piece is knowing which types of lights you will need to use in order to achieve the desired effect, specifically in this instance knowing when to make a change to their mobility setting in Unreal. To start our discussion on mobility in this chapter, you will notice that we currently have lights in the scene that have big red axes attached to them. This warning is linked to the mobility choices that have been made for the lights in this particular scene. In fact, if we click on one of them and look in the Details tab, you can see that it is actually set to Stationary Mobility, meaning this light can function as a blend of either a static or dynamic light. As the name suggests, Stationary lights cannot move or change their position at runtime, so if, for example, we had our spotlight here turning when we ran the level, the Stationary setting simply wouldn't work for us, as we would instead need to use the Moveable option. Unlike completely static lights though, lights set to Stationary can change their intensity and colour at runtime, and so if we wanted to add a light dimmer that the client could adjust whilst running the level, then a setting of Stationary would work just fine. Now we bring this to attention because Stationary lights store shadow information inside a shadow map, or more specifically inside each channel of a shadow map. As these maps only have four channels available, so RGB and A for Alpha, if we have more than four Stationary lights overlapping in a scene, the ones with the X attached in the view are the ones that won't be calculated, although adjusting the cone and attenuation values of our lights so that they do not overlap will fix this problem. If our light isn't going to move in the level though, or change its colour, or intensity at runtime, then I would say that it is probably best to make sure it is set to static, as these light types have pretty much zero computational overhead at runtime. Let's select all of the lights in the scene then, all except the spotlight facing the stairs, and let's change the mobility setting to static, and as you can see our warning icons now disappear. We have left the stair light set as Stationary in this instance because we will be coming back to look at how we can control light intensity at runtime a little later on, and so we'll use this light to do that. Now what advantages, if inner, do static lights have? Well as mentioned, they have very little to no computational overhead at runtime, and by default, they work as area lights with area shadows, which instantly gives them a more realistic quality. To keep in mind though, that because static lights need to be baked down into light maps, their final quality is directly affected by the light map resolution of the meshes that we have in the scene. And because light maps are being used, and obvious disadvantage of static lights is that, well they can't change intensity, colour, or position at runtime, given that the light and shadow contributions have been baked into a fixed bitmap. What about movable lights then? Well these do have the advantage of casting dynamic real-time shadows into a scene, meaning that if a door opens or an object moves in the level, then this light, unlike the other two, can cast a shadow that updates and moves in real time. As these are naturally more computationally expensive though, it is probably best to use them in combination with other light types in order to get the most realistic result from them. Knowing the situations in which we may want are, need to change a light mobility setting, is fundamental to getting a good lighting solution in Unreal. And so, taking the time to figure out what we want our need from each light in the scene, will certainly help us make correct decisions, farther project that we are working on.
