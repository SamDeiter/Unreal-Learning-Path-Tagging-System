As with our automatic doors, this blueprint contains a number of actor types, and so not only do we have our static mesh actor, this being the light housing, but we also have two light actors providing the illumination. The lights are set to be movable, which means that we can change the intensity at runtime, whereas static lights wouldn't work in this particular situation. We will need to access the two light actors properties then, and so, from the Components tab, let's drag out a reference from the Spotlight and Spotlight One Components. Just like the sliding doors in our last example, we now have a reference to each light in the blueprint, which means that we can change them either individually or together depending on the needs of the project, although in this instance we will control them together. Before we set up the light switch, let's go ahead and tell our lights what to execute by right clicking in some empty space, and then performing a search for Custom Event. After which we can choose to add the Custom Event option, then give it the name switched. Meaning this Custom Event can now be accessed from outside this blueprint and told to execute. Whatever we add after this node now, we'll run every time the blueprint is told to execute the switched Custom Event. Let's continue setting up the logic for the flow then by dragging from the Custom Event's execution port, and then searching for and adding a flipflop node from the flow control section. In this instance, we know that the lights we will be controlling are only going to be either on or off, hence the flipflop node, which does just as it says, and switches between its A and B execution ports each time that it is called into action. We need to tell the flipflop node what to do still, and so let's drag out from our spotlight reference, type set intensity into the search field, and then add the node of the same name from the light section. After which we can pipe our spotlight one into its target slot as well, setting its intensity to a value of 0. As you can see, we are able to control both lights with a single set intensity node here, thereby making the blueprint really efficient. It should be noted that our lights are starting with a positive intensity value, and so our turn on, meaning we need to make sure the first flipflop, so the node's A output, sets the intensity to 0 or off. If we start with lights that are off by default of course, then we will need to reverse this order. To enable us to turn the lights back on, we can once more drag out from the spotlight reference, type set intensity into the search field again, and then add another node of the same name, after which we can pipe our spotlight one reference into its target input, and set its intensity value at 200. Essentially making it so that if the lights are off, then they will be turned back on. Now if we wanted to alternate between top and bottom lighting, we would simply make sure that one of the lights in the actor starts with an intensity of 0, and then remove the appropriate light from each set intensity node. When we press the switch then we would change from up lighting to down lighting. Moving back to our example, at this point in time nothing will actually execute, and so let's pipe our A execution port from the flipflop node into the first set intensity node, and the B execution into the second set intensity node. Now whenever the blueprint is told to execute, it will flipflop between the two intensity states that we have created, these of course being off and on.
