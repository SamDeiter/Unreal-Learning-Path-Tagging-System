Building upon the system we made to use local spatial anchors to store on our device, now in this module we will prepare our project to use Azure spatial anchors that are stored in the cloud and shareable to other devices. We're going to log in to access the Azure portal to create a new resource. Doing so will also give us all the information we need to connect our project to our Azure account. Let's get started on azure.microsoft.com. At the top nav bar select products. Azure has over 200 products for a wide range of needs. What we are searching for is spatial anchors. The account is free to make as are 10,000 anchor locate requests per month. Definitely enough to get us started. After you create an account or sign in, access the Azure portal. Open the left menu and select create a resource and search for spatial anchors. Click create. We need to provide some information to this new spatial anchors account. I'll set the resource name to world builder anchors. Because I have no subscription, keeping it at pay as you go is fine with me. Of course, if you have a subscription setup for this purpose, you could set that here. We need to add in a new or append it to a current resource group. As we saw, Azure offers many services and if your app uses several of them, they can be grouped together. World builder only uses one, so I'll of course name this resource group, world builder. Set the location of where the app is to be primarily used. Doing this will provide the fastest service when trying to access your cloud data. Click create and the portal will validate this new resource. It shouldn't take too long to complete. With our new resource ready, select go to resource. Here's an overview of the anchors made. As you and your users access them, that information will be viewable here. The information that we will need to access this resource from our project is the account ID, the account domain, and the keys located under settings. Inside of Unreal Engine, open the plugins menu. Search for Azure WMR if you're using an Android device. Search for AR core and if you're using an iOS device, enable ARKit. And of course, Azure spatial anchors at the top. Go ahead and restart the project. We'll need to start a new spatial anchor session to read from and write data to our resource. I'm going to place this logic inside of our BP PON. Create a new custom event named start azure session. Write click and search for create session. From the return value, create an AND node and plug this into a new branch. We only want to try to make the connection if the AR session is running. So write click and search for get AR session status. Break the session status and from status, check if its value is equal to running and connect to the AND node. From true, search for config session. Drag backwards from session configuration and search for make Azure spatial anchor session configuration. In the details panel, we only need account ID, account key, and account domain. Paste in your information here. Next, create a start session node and check if it was all successful. Because we will want the option to stop the session, promote the return value into a variable. I'll name mine azure session running. Create another custom event named stop azure session. Add on a stop session node, a destroy session node, and set azure session running to false. Make sure to call our start azure session at the end of the prepare for AR event, as well as stop azure session at the end of end play. Before we move on, let's make sure our app can connect to the internet to make these requests. Open the project settings and scroll down to HoloLens. Make sure internet client, internet client server, and private network client server in the capability section are all set to enabled.
