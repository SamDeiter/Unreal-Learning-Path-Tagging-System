Like the variables in arrays we just explored in the last lesson, data tables stored data. Data tables however are read only once within UE4, but do contain the useful structure of a spreadsheet. They can be employed in a variety of ways. They also allow for outside members on a team to contribute to a project. We will go more deeply into data tables later, but for now I just want to show you how to create, import and use this extremely useful tool. Generally I use them for user feedback on product information, but they can be employed to great effect in a multitude of ways. Let's just make a very simple example and walk through the steps. I'm going to use Google Sheets, but feel free to use whatever spreadsheet tool that can output a CSV or a comma separated value file. The CSV file is also in the project folder, so if you want to skip this part you can just use the one provided when we get to importing. Here I am in Google Sheets. The first thing that I need to do is create a header line. Across the top let's define the columns as UE underscore item underscore name, then item underscore name, and finally item underscore description. In the first column number them 0 through 2. In the second column I'm going to put cool cups, super cups and mini cups. Then in the last column I'm going to put keeps your drink cold, simply unbreakable and small cups for small hands. I'm just going to export as a CSV file and put it somewhere I can find it. Now we have our CSV file, unreal however does not know how many columns your data table will be or what kind of information to expect. Therefore we need to define the structure for it. Let's go ahead and do that. In UE4 again let's jump back to the root of our project and create a new folder called data tables. Now double click it. Our first column is used by UE to auto increment and give each line a unique ID. So we do not want to define that column. Instead we will just start with our second column item name and set the type to text. Let's hit the new variable button and add our second column definition. This time let's call it item underscore description. This one should also be set to text. Now we can save and close. Now all we need to do is import our spreadsheet. Let's go ahead and click the import button and select our spreadsheet. In the next window select products from the list for data table row type and click OK. You now have your spreadsheet imported. Let's double click to review it. You should now see a mirror to your spreadsheet data. We have the data in but how do we put it to work? Let's jump back into our level blueprint. Let's find a clean space in our level blueprint and right click. Type in two and grab the two input event node. dragging out from the two event type in get data table row and select the node. Next select your products data table in the drop down. Now let's add a random integer and set the random value to three. From the integer output drag and type two string. Now from the string you can drag to the row name and it should automatically convert from string to row name. This bit is a touch annoying but basically all we are doing is taking a random integer and converting it to a string and then to the row name. Each conversion being a change in data type. It's just a necessary evil. With the get data table row we will get just that. A row of data. This is still not very useful to us yet. What we need is the contents of the individual columns. What we will want to do is break the row. From the out node let's drag and select the break products. As you can see it automatically populates the node with the item name and item description from our headers. Now let's just print out the columns. Right click and add a string append node. Let's feed the item name into a and the item description into b. Let's drag out the return of the append and add a print string node. Lastly, let's just connect up our event. Compile, save and give it a play. Now by pressing two I can see a random product and description in the debug message on the top left of the screen. This was a rather useless example as we could do this just as easily with variables and the like. However, it does show the process for using a data table.
