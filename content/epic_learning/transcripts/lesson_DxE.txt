Now that we have a very basic understanding of just what Blueprints are, we're going to take a quick look at the types or flavours that Blueprints come in. And although we will only be using the Blueprint class to build our examples, it is good for you to know that there are other types of Blueprint available and have a little bit of insight into what they do. Even if we don't fully understand all of the information, it will be a useful reference for when we move on to using more complex types of Blueprints. The Blueprint class most commonly referred to as just a Blueprint will probably be the most used Blueprint type when it comes to everyday visualization projects, as these allow us to add functionality and wrap up the content in a nice easy-to-use package. These Blueprints can, for example, contain lights, static meshes, and collision boxes that the Blueprint graph can then access in order to add embedded functionality, something that we will see in action throughout the course. A data-only Blueprint can contain variables and components that it inherits from its parent, these Blueprints allow us to adjust any data that gets fed into them. Unlike the previous Blueprint type, though, we can't actually add anything new to a data-only Blueprint, it can only use whatever we feed into it. These can be used then to create items that might have changing properties or values, which might be helpful for the product visualization feel. Level Blueprints are created as the name suggests with each new level that we add to our visualization. These can be very useful inside these types of projects, as they allow us to fire our execute level-specific sequences such as camera animations and events, meaning we can make sure that a client sees a special part of the visualization just at the time that we want. The Blueprint macro-library is really cool in that it can be used as a mini-time-saving device, in that this Blueprint type can store a number of self-contained graphs that themselves contain commonly used node sequences, the type that we may want to add into Project after Project. These macros then can be added as nodes into other Blueprints, making them very useful, as we say, for projects that may share similar functionality. Two other Blueprint types available that we won't go into here are Blueprint Interfaces and Blueprint Utility Types.
