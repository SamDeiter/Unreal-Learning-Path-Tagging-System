Before we get into the creation of this 2D player character, I think it's important to understand the fundamental differences between a Paper 2D character and a traditional 3D character you may already be familiar with in our real engine. In this video, we will take a quick look at all the components that make up the included 2D character and see how they compare to what you might expect from a 3D character blueprint. Let's begin by opening the 2D character that was provided with a starter content and take a closer look at each component. Using the content browser, navigate to content, 2D sidescrawler BP, blueprints, and double click on the 2D sidescrawler character to open the blueprint. Let's switch to the viewport tab by selecting it so that we can see each component on the character as we selected. Let's start by focusing on the components that this blueprint shares with a 3D character blueprint. We're working our way through the components using the components panel on the left-hand side. The first component is the capsule component, which is used for handling simple collisions between the character and other objects. In our case, this interaction will come from the collision volumes we defined in the tile cell we created previously. Next is the arrow component. This serves the same purpose for both character types. It helps us visualize which direction should be considered forward when performing certain logic on the character. Next is the camera boom. This is a spring arm component. It is used to maintain a certain distance between the character and the camera, which is attached to the other end of the boom. The attempts to do this in a graceful manner, rather than having the camera directly attached to the moving character. Speaking of the camera component, both character types will tend to have a camera component. The only difference here is that our gameplay camera will be using an orthographic projection. Next is the character movement component. This component is used to handle all the movement logic for the character. The only difference between our 2D character and a 3D character is the specific values within this component and the planes within which it's allowed to move. And finally, moving away from the components panel for a moment, the event graph. The event graph is used to handle player input. The key difference here is that we will also be using the event graph to handle the animation state of the 2D character. The use of the event graph to control animation state brings us to the biggest difference between the 2 character types. If we return to the viewport and look at the components panel, we can see that the character has a sprite component with an associated flip-flop animation. This is instead of any sort of skeletal mesh, use of blend spaces or animation state machine. This means the logic we had for implementing features we may get easily for 3D characters will not apply here and will have to tackle by ourselves in an upcoming module. In this video, we took a high level look at the differences between a 3D and a 2D character when it comes to Unreal Engine. We saw that the majority of the components are exactly the same. Both have a capture component for basic collision checks, an arrow component for displaying facing direction and a camera attached by a spring arm component. We learned that the fundamental difference between the 2 is the way that they handle animation. A 3D character has a greater range of inbuilt tools, an animation state machine and the ability to blend between multiple animations. In contrast, a 2D character is much simpler. The character has a sprite component which can be set to play a flip book and not much else. We must add the functionality ourselves to the event graph.
