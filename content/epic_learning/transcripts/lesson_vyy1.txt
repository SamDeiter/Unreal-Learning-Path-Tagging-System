Besides a new coat of paint, the engine has had some changes that we want you to be aware of, so we're going to take some time to point these out in an effort to make your transition smoother. Removed, the legacy audio back in. This has been defricated as of 4.27 and will be removed in 5.0. Defricated, the old audio system. The system that uses volumes sound class mixes and cues has been defricated as of 5.0 and it will be made obsolete by MetaSound. Removed 32-bit platform support will be removed in 5.0 as most supported platforms are currently 64-bit and the event-driven loader, the old loader system, has been replaced with the new Zen loader system. Defricated, the stat system has been defricated in 5.0 and is being replaced with the Unreal Insights system. Removed Blueprint Nativeization. It should take no work on the part of you as the project user. If you did leverage this feature, it's been disabled and the project should still function. Removed, the legacy socket system, it was made obsolete by ASIO and unused packet encryption. Only DTLS is currently going to be supported. Defricated, FizzX, it has been made obsolete and has been replaced by the Chaos Physics system. Removed, Support for Visual Studio 2015 and 2017. 2019 is the current minimum supported version with support for 2022 being considered experimental. The legacy C++ Hot Reload system has been replaced by the LiveCoding Plug-In for Windows. A noteworthy change. DotNet Core will be the DotNet runtime for Unreal Gamesync, Unreal Build Tool, Unreal Header Tool, and the Unreal Automation Tool. The DotNet Core 3.1 redistributables will be installed for all Unreal Engine 5 users. If you do intend to compile or debug, you may need to install the DotNet Core 3.1 SDK for your IDE to work. We'll be standardizing all target platform names. If it was before, for example, Windows No Editor, it's just Windows, and Windows itself with the Editor is the Windows Editor. Build scripts will need to be updated to use these new names, and if you do use device profiles, you may need to update them as well. The legacy tone-mapper, it has been deprecated for two years at this point. The distance field GI system, it's been replaced with the Lumen. Light propagation volumes have been made obsolete by Lumen, and hardware test-relation as well has been made obsolete by Nanite. Deprecated, the Cascade system, it has been made obsolete by a Niagara. It will be removed in the future. A conversion path will be available before it is removed. The legacy editable mesh plugin has been replaced by the new geometry editing tools. Movie scene capture has been replaced by the Movie render queue. The sequence recorder has been replaced by the take recorder, and camera anems have been replaced by camera animation sequences. For deprecated, Metnae has been made obsolete by sequencer, and there is a conversion path available if you're still using Metnae. World composition has been replaced by World partition, and BSP has been replaced by the mesh editor tools for creation. I'm still using BSP, however BSP for creating blockouts should be now using the mesh editor tools. A few other things I thought might be worth noting, the ANCEL plugin has been removed as a 5.0, and a few important changes. The duplicate hotkey has been standardized. It is now controlled D across all of the editor, a USB control W. UMG widgets no longer have a default panel as the root. You do have the ability to restore this functionality in the project settings. You can change it back to have a default panel. It doesn't have to be a canvas panel anymore, it can be any panel as the default when creating a new widget. There is now an additional setting for when you are creating a user widget to define which panel is used when you create that widget. And creating a new C++ class is now in the tools menu instead of the right click content browser.
