The concept of debugging as a whole can apply to any work you're doing inside of the engine as well. With the methods we covered in this course, you'll have an idea of what you can do to validate your data as you use it as well as identify your possible issues you might encounter. We started by looking at the ability to print string or put the data in an easily accessible place on your screen and in your log. This is useful when we need to validate or check or verify something is actually what it's supposed to be. Then we looked at break point debugging. This is a standard feature of most development systems using the break point to pause execution of code, see what the current values are of everything that you're working with and then walk through your code line by line or node by node. We use the blueprint debugger window to have an easy view into what is going on in our project at the current moment as well as the ability to look at the data flow for individual blueprints in a nice organized window. Debug shapes can be used to visualize that data in well a visual format. We have a variety of different debug shapes and types and values that we can use to easily see that data and then maybe that would let us know what is going wrong when working with a larger blueprint and you may need to reroute things that are going on or temporarily not do something rather than rewiring your code up. You have the ability to mark nodes as enabled or disabled as well as flag them for development only so that way you can easily change the flow in your editor without having to rewire everything. This was just a quick look at some top level methods of blueprint debugging. There are much more advanced methods so look out for other courses on those methods as well as the official Unreal Engine documentation on the Unreal Engine website. Remember when you're working on a project problems can and will happen. It is a normal part of the process. By using these methods to track down those issues you can get a clear picture of those issues and start working towards fixing them.
