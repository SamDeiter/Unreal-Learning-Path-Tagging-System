The first step when using Unreal Engine containers is to obtain a suitable container image. The engine ships with two distinct types of container images, and it's important to choose the appropriate image type for your use case. The first type of container image is a development image. Development images contain the Unreal Editor and Build Tools, and they're designed for use cases such as continuous integration and deployment, rendering cinematics, automating production pipeline tasks, pretty much anything that requires the full engine tool chain. Because they include the full editor and associated tools, development images are extremely large in size, and the distribution is subject to the same terms that govern distribution of the editor itself. This means these images can't be shared publicly, but you are able to share them privately within your own organization. The other type of container image is a runtime image. runtime images don't actually contain any Unreal Engine components at all, but are instead designed to encapsulate a packaged Unreal project and provide the dependencies that it needs in order to run. This makes runtime images significantly smaller than development images, and it also means that runtime images can be shared publicly without any restrictions. We're going to be downloading a development image today, but the process is the same for both types of images. If you want to follow along, you can find step-by-step constructions on the container's quick start page of the Unreal Engine documentation. All of the official container images for the Unreal Engine are stored on GitHub alongside the Engine Source Code. To access either the Source Code or the Container Images, you'll need to link your GitHub account to your Epic Games account by following the instructions provided on the Unreal Engine website. The linking process only needs to be performed once, so if you've already linked your account in order to access the Unreal Engine Source Code on GitHub, then you're ready to go. Once your GitHub account is linked to your Epic Games account, you'll need to create a personal access token in order to download container images from GitHub Container Registry. Simply follow the instructions from the GitHub documentation, making sure you tick the read packages scope when creating your token. It's important to remember that this token can be used in place of your password when authenticating with GitHub, so be sure to keep it safe and don't share it with anyone. Once you have your personal access token, open a terminal or command prompt and use the Docker login command to authenticate with GitHub Container Registry. You'll need to enter both your personal access token and your GitHub username here. If you've entered your credentials correctly, then you should see the message Login-Succeeded displayed on the screen. It's worth noting that I've used a quick dummy value here since I'm already logged in, but a real personal access token will be much longer than six characters. Now that you're authenticated, you can use the Docker pull command to download a container image. I'm downloading the development image for Unreal Engine 427 here, but you can see the full list of available images on the containers overview page of the Unreal Engine documentation. If you've never used a container image before, then you may be curious as to why there are multiple progress bars displayed during the download process. This is because container images are actually broken down into a series of individual layers that stack on each other, and the layers are downloaded in parallel to improve the download speed. You'll also see that each layer is first downloaded and then extracted before its status is listed as pool complete. This is because the layers are compressed before they're downloaded in order to reduce the amount of data that needs to be transferred over the network. Even with these optimizations, it still takes a while to download an Unreal Engine development image due to its large size, so I'll speed up the video here. Once the download process is complete, you should see the message downloaded newer image displayed at the bottom of the screen, along with the container image name. The image is now available on your local system and ready for use.
