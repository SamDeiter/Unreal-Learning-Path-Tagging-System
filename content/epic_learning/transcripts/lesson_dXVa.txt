For this module, we will be focusing on importing, cleaning, animating and rendering point clouds within Unreal Engine. The goal of this module is to empower you all with the knowledge to apply the same techniques quickly to your own LiDAR point cloud files. I would recommend that where possible LiDAR point cloud files are imported either as E57, LAS or LAZ file formats. I'd also recommend that these files are kept to approximately seven gigabytes in size or under. Within many LiDAR registration packages, LiDAR datasets can be split into smaller parts, or individual scan positions can be exported once the registration process is complete. The reality capture team have put together clay tools that can be used to split reality capture LiDAR exports into smaller pieces. You can find a link to the clay tools in the documentation and we will show this link in the overview section of the course. In the root folder of the project, you will find a zip file called realitycapture.zip. Within this zip file, you will find all the files you need to follow along with this course. For this course, we'll be working with Unreal Engine 5.2. Create a new Unreal Engine 5.2 project. Here I've used a blank architectural template, but you can use other templates or create a blank project from scratch. Once opened, navigate to the plugins window. We need to search for LiDAR and you should see the LiDAR point cloud supports plugin as an option. Click the tick box to activate it, then restarts your project. The first thing we will check once the project restarts are the project settings. Navigate to edit project settings and scroll down until you reach the LiDAR point cloud heading in the plugins section. Here we can see that the auto center on import setting is currently turned on. If you are importing your point cloud files and see that Unreal Engine doesn't respect the coordinates that you saved with the point cloud files, uncheck in this value, will then bring in your files at their predetermined locations. With the point cloud plugin enabled, we can now drag and drop the .las file from the extracted zip folder into our editor content browser. Depending on the size of your files, you may have to wait a few moments for the point cloud to populate here. We can preview the file by double-click in on it in the content browser. Our preview window will also display the number of individual points this asset consists of. Drag the point cloud asset from the content browser into your scene. Then in the outliner, make sure that the point cloud actor is selected. In the details window, set its position to 0000 on each axis. By default, when we activate the point cloud plugin on a project, we will not see every point, but instead a smaller percentage overall of points that run smoothly within the 3D viewports. We can override this at any time using the following console command, r.lider.budget. We follow this by a space and the number of points we wish to capture. The higher you set the number, the more overall points will appear, and we can switch between higher and lower numbers of points whilst we undertake different activities in the engine. When you enable the point cloud plugin on a project, you also enable a new LIDAR mode with a powerful selection of point cloud tools. In the top left-hand portion of the screen, switch from the selection mode to the LIDAR mode. When we capture LIDAR datasets, sometimes it's unavoidable, capturing pedestrian and vehicular activity in scans. And sometimes it's helpful to strip away portions of point clouds to reveal hidden details. We can use the selection tools to isolate any areas we want. For instance, here our selection shows a cross section through the structure. We can change the visual style of our point cloud actors quickly in the actor details window. By default, it will use the RGB data associated with each point on import, but we can change this to height-based colourisation, classification values, or just single colours. To add additional effects to the point clouds, we can set an override material. Create a material in the content browser, rename it, and then navigate to the material graph. On the course module page, you will find an embedded code snippet. We can copy the snippet from the course module page, then use control plus v on Windows, or command plus v on a Mac to paste the snippet content as a series of connected nodes in our material graph. When you paste the snippet into the material graph, the results should look like this. Click the results node of the material, then in the details section, change its blend mode from a peak to masks. Now back in the material graph, we need to reconnect each segment to the masked results node. Firstly, connect the colour overlay linear interplay's Lurp node to the base colour. Connect the zero value constant node to the metallic in specular. Connect the one value constant node to the roughness. Connect the multiply node to the emissive colour. Connect the one minus x node to a pastime mask. And finally connect the multiply node inside the gap fill in section to the pixel depth offset. Click apply and save, and your material preview should look like this. Connect set up a quick material parameter collection. Right click in content browser, and within the material section select a material parameter collection asset. Open it in the content browser, and create two scalar parameters called height1 and height2. Set the value of the first parameter to 530, the second parameter to 900, save the asset, and then return to the material we just set up. In the material graph, right click and type collection, create a new collection parameter node. With this node selected, change the collection value in the details tab to the newly created NPC assets. We can then select height1 as the parameter name. Change this node to the subtract node B value. Scroll down to the clamp node, and create another collection parameter node next to it. This time in the details tab, change the collection value to the new NPC file, selecting height2 to the parameter name filled. We then need to connect this to the clamp node max value, and the divide node B value. Now, if we set the new material to the point cloud actor custom material filled, we should see the cross section effects. And from here onwards, we can control the height of that cross section effect by modifying the two scalar parameters in the material parameter collection asset. We can control NPC parameters through Blueprints and also in animations. In the content browser, right click and create a level sequence from the Cinematics category. In the level sequence window, click on add track, and you'll notice that we are able to add a material parameter collection track. Select the new NPC asset we have created in the content browser. Over on top of the plus symbol on the track, click parameter and add both height1 and height2 values, expand the track, then add two key frames at frame0. Click to the end of the sequence, then change the height1 value to 60 and the height2 value to 200. Now if we playback the sequence, we can see that the cross section effect is animated. Now that we've seen how we can animate the point cloud, let's quickly run through some considerations for rendering. If your point cloud has a sparse resolution where you can easily see through gaps between points on captured surfaces, consider changing the gap fill in strength on the point cloud actor details tab. Here if we leave the value to its default zero, we can easily see through this surface. If we change this value to 300, most of the gaps are now filled in. Sometimes it's also worth lowering the point size in combination with an increase of the gap fill in strength to find a suitable balance. We can modify some of the lidar point cloud settings in our project settings. Turn off fast rendering. Turn off prioritise active viewport. Use the cached node lifetime and also increase the max bucket size. Also consider pushing the command console r.lidar point budget to a high number for rendering. The higher the graphical performance on your machine, the higher you will be able to push this number. Now that we have our settings changed and a level sequence set up, we can push those results to the movie render queue. Ensure that the movie render queue is enabled in your plugins section, then add your level sequence to the movie render queue job queue. There isn't anything additional here that we need to specifically consider to get good results for lidar renders.
