Open our new Blueprints folder and then right click in the content browser select Blueprint class from the Create Basic Assets section. This will open the Pick Parent class window. Once we've expanded the rollout we can begin searching for Paper Character to locate the Paper Character class. Once we can see the class we want we can click it with a mouse button and hit select at the bottom of the window. This will create the new asset in the content browser, prompting us to name it. Let's get started by configuring the default idle animation for the character. Select the sprite component from the Components panel on the left hand side. With the component selected locate Source Flip Book in the sprite rollout of the details panel on the right hand side. Click the drop down box and type idle. This should be enough to locate Flip Book underscore UE4 robot underscore idle stand, which we can then click to select it. If we take a look in the Viewport tab we can now see our idle animation play. But there's an issue. If we select the Capture Component from the Components panel we can see that this is much larger than the sprite. To make it easier to line up let's adjust the Viewport camera to an orthographic perspective. Use the Viewport toolbar to change from perspective to right and then change the rendering mode from wireframe to unlit if necessary. We can now use the mouse wheel to zoom in for a closer look. Ensure that the Capture Component is still selected and then locate the shape rollout in the details panel on the right hand side. Select the Capture Half-Height to 32 and the Capture Radius to 20. That looks much closer. However if we zoom right in on the character we can see the bottom of the Capture extends just below the feet. If we left it like this there'd always be a gap between the characters' feet and the tile map visually and that's not what we want. Luckily this is easy to fix by applying a small offset to the location of the sprite component relative to the Capture Component. Select the sprite component from the Components tab and locate the Transform Rollout in the Details panel. Adjust the location Z to minus 2. Now we can see that the very bottom of the Capture lines up much more closely with the bottom of the character's feet. And with those few changes we've configured the sprite and Capture Components of our character. The next step will be to configure the basic camera system to follow this character around. Now we need to go ahead and start adding new components. As we saw previously during our tour of the starter content character, a spring arm is useful to separate the movement of the camera from the character. Unreal has built-in functionality for this with a spring arm component, so let's go ahead and add one of those to our character blueprint. Ensure that we have the character itself selected in the Components panel and then click the Add Component button above. Then typing spring arm until you can see it in the search results. We can click to select the spring arm to add it to our character. We're prompted to rename it, but in this case I think spring arm is a pretty good name so we can press Enter to accept that name. In order to appreciate what the next few changes are actually doing to our blueprint, we need to switch the perspective camera in the viewport. So let's change from the right view to the perspective view in the viewport toolbar. We can now see our spring arm represented by a red line and there's a slight issue. It's connecting to the character at the wrong angle. If we group position the viewport camera to follow this angle, we can see that if the camera were attached to the end of it, it would be looking towards the character from the side. As our character has no depth in this dimension, we're going to be looking at nothing, which we probably don't want. Let's go ahead and fix this. Ensure that the spring arm is still selected in the Components panel, locate the rotation values within the Transform rollout and set the Z rotation to a value of minus 90. Now if we reposition our viewport camera at the end of the spring arm again, we can see that we'll be looking directly towards the front of the character, which is what we want. We're nearly done with the spring arm. We just need to make a few more adjustments for a camera system in a 2DK. The biggest difference for our camera settings compared to a traditional 3D camera is that we do not want to inherit the YOR move from the character. If you're like me and always forget which axis is which, let's quickly demonstrate that. Select the sprite component from the Components panel and press E on the keyboard to activate the rotation widget. Now select the blue part of the widget and move the mouse. As we rotate the widget, you'll note that unreleangible helpfully labels this axis as your. Now our character is never going to rotate around this axis, but what they will do later on is flip 180 degrees in order to face the other direction. If our spring arm component followed this motion, the camera would also flip 180 degrees, which is definitely not what we want. Let's once again select the spring arm component from the Components panel. Make sure to uncheck inherit YOR in the camera settings rollout. We can safely leave pitch and roll as they won't actually influence our particular camera. The last thing we need to do here is enable porn control rotation. We can do this by checking that use porn control rotation option in the camera settings rollout. For more complex 3D characters, this often isn't what we want, but in our case we can safely use the porn control rotation at all times. Now that the spring arm is correctly configured, all we need to do now is attach our camera to the end of it. Ensure that the spring arm is still selected in the Components panel and click the Add Component button. Search for camera and press Enter to select it. Once again, we'll be prompted to name this new component, but I think camera is a very good description so we can press Enter to confirm that. If we take a very quick look at the hierarchy in the Components panel, we can see that the camera is parented to the spring arm. This means it will follow the transform of the spring arm we just configured. If we turn our attention back to the viewport and zoom out a little, we can see that the camera is in the right position, but it's facing the wrong direction.
