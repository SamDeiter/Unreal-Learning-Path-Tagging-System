The main motivation behind the new interchange framework was to, if you import files into the Engine, depending on the different file format you're importing, you end up having different codes, perhaps doing similar things like creating assets and everything. The goal is to have a modular framework where most of the imports are going to follow the same frameworks, the same steps. Same for having, when you have factories to create your assets, be able to use the same factories for different types of imports. What we have now is you have the interchange framework that does the orchestrating the import and then you have different translators for the different file formats. But then the factories, we try to reuse the same factories. It comes with different benefits. We make it a bit more open so it's easier to customize it, so change settings for when you're importing, create presets for your import settings. Also extends the existing processes for importing and even go to a way to add your own translator if you want to add your own file format support. For us, because it's modular, it's easier to maintain, and that means also it's going to be more stable. If you're importing several files at the same time, if you're doing a batch import of textures, GLT, things like that, then each single file is going to be imported in parallel, so you get some benefits there also. So far, the work has been focused on the import part, but we are thinking in the future to also use this framework for exporting files.
