By hitting tilde and typing, stat FPS, we can see the current frame rate. Using stat unit, we can see the time taken on the GPU and the CPU for rendering. Stat scene rendering and stat game can help us identify CPU related issues. These are all commonly used commands to help get a broad understanding of hardware usage. But what about memory usage? Broadly speaking, memory is used to load and store textures in a scene so they can be rendered in the viewport. Eventually, in a large project, you may notice a warning in the top left corner of your viewport that says streaming pool size over some amount of megabytes or gigabytes. The texture streaming system in Unreal Engine is responsible for loading and unloading higher and lower resolution textures. This system is in place to help us achieve a high level of visual fidelity while still hopefully making efficient use of available memory. So when we receive this warning, that means that we do not have enough memory allocated to Unreal Engine to display the highest resolution textures when we need to. In this case, we could find out what is taking up so much memory and resolve that issue, or we can simply increase the amount of memory available for Unreal Engine to use. The first likely problem could be that we have too many high resolution textures being used in the viewport when we don't really need them. Go up to Window, Statistics, and choose Texture Stats. With everything fully loaded in the scene, this project is only taking up around 280 megabytes, definitely not bad. In huge project files with exterior foliage or tons of different assets in the scene, this could be much, much larger. Sort by fully loaded memory usage to see if anything is taking up an inordinate amount of memory. This dirt normal texture is an 8K detail texture map that is only really visible from a close view. For projects where you know the user can and will be close enough to an object, this might be fine. But in my case, I'd like to reduce this size. To do so, we can find it in the editor by clicking the name, open the file, choose the drop down under compression settings, and change the maximum texture size to be a smaller power of tube value. I'll set this to 2048. Save the texture and go back to the Statistics window. Now, if we refresh, we can see that the total memory usage is much, much lower. If any of your textures being used are not power of two textures, they may also be severely impacting your memory usage because they don't have lower midmap textures to switch to. To resolve that issue, you could again open the texture, and under Power of Two Mode, use an option to pad the texture to a higher value. Alternatively, you could simply edit the texture in your digital content creation program of choice and re-import it. If you simply need to allocate more memory to your project, you can do so with a console command. Type streaming.poolsize and a number to determine the amount of megabytes you would like to be available for streaming textures. We can see a great breakdown of total memory usage by typing stat memory. You may want to keep an eye on these values as you develop your project so you don't have to work backwards to fix memory issues later on.
