One of the most common game development use cases for Unreal Engine containers is building and deploying dedicated servers. Server deployments are one of the things that containers do best, and so this particular use case has gained widespread adoption. Here we have the source code for the third person template project that ships with Unreal Engine 427. The project has been configured to make use of a dedicated server, and two files have been added to make use of containers. The Docker file provides the steps needed in order to build and package a dedicated server in a container image. The file dot Docker ignore specifies a list of files and directories that should be excluded from the container build, which speeds up the build process. This is particularly useful when the project has already been built and packaged for the host system, as is the case here. If we have a look at the contents of the dot Docker ignore file, we can see that it's just a simple list of files and directories to exclude from the build process. The files in these directories can be quite large and aren't needed in order to build the dedicated server, so it's best to exclude them from the build process to improve its speed. Having a look at the Docker file, there are two main sections of code. The first section of code uses the Unreal Engine development container image that ships with Unreal Engine 427 to build and package the dedicated server for the project. The second section of code then copies the packaged files into a minimal container image for deployment. It's important to note that a dedicated server doesn't need to perform any rendering, and therefore doesn't require any of the dependencies in the runtime container images that ship with Unreal Engine 427. Instead, we copy the packaged files into a Google, distro-less, base image to ensure the final container image is as small as possible. To build the container image for the dedicated server, use the Docker build command. This process can take a few minutes, so I'll speed up the video here. Now that the container image has been built, run the container using the Docker run command. Note that we expose UDP port 7777 here to ensure that game instances can successfully connect to the dedicated server. The dedicated server is now up and running, ready to receive new connections. We'll start two instances of the project here to demonstrate the use of the dedicated server. Note that we're instructing the game instances to connect to the dedicated server by specifying the loopback address 127.0.0.1, since they're running on the same machine as the server. As you can see, the two game instances are now connected to the dedicated server and sharing the same game session. As we interact with the game world in one instance, the Unreal Engine's networking code automatically replicates the game state to the server and to the other instance. With just a couple of configuration files and commands, we've built a container image suitable for deploying our game's dedicated server to the cloud. When you combine this with container orchestration technologies such as Kubernetes, you have the initial foundations for building a massively scalable online multiplayer game. This is just one of many development workflows that can be simplified by the new container support in Unreal Engine 427.
