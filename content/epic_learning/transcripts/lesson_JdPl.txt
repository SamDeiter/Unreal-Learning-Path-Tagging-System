Welcome to developing for the HoloLens 2 in Unreal Engine 4. This is at 11 course learning path designed by Microsoft's HoloLens 2 team and Unreal Online Learning. If you have been following along through the learning path, welcome back. If you would like to follow along from the beginning where we prepare Unreal Engine for mixed reality development, find this learning path on the Unreal Online Learning course library. This is course 9 where we will use tools and principles for project optimization to find the balance between features and performance. We will move through the standard steps that are required throughout the cycle of project development. The projects that are created by us and our teams would be wasted if we did not take the constraints of the target hardware seriously, as the project can become unstable, unreliable, or unable to run altogether. Taking steps to make sure that the project runs as expected is essential to providing a usable and effective experience. To be sure, this course will not help fix every problem that your projects may run into, but we want to provide a basic checklist of things to remember that can help guide your projects to be as optimized and ready for end use as possible. Our project, of course, is being built for the HoloLens 2. This device has some strict constraints that we need to satisfy to maintain a minimum of 60 frames per second. The stability of our project and, more importantly, the comfort of the end user depends on it. We will optimize our World Builder app that we have been building over this learning path. We started with the blank project and, over each course, have continuously added more and more features to it. Some of those features, for example our gaze tracking, run constantly and are updated every frame while we are in the app regardless of if we are using the data. Our BP PAN is now a heavy blueprint of constantly running mechanics that are not always needed. We will need to allow the user to toggle these functions for use when necessary. Being able to switch to an all gaze tracking project from a hand tracking project or voice command project would be a dynamic solution to allow many types of interaction. But we don't need to have all of them all running at all time. Back in course 2 of this learning path, after getting our project prepared, we imported pre-built assets that we simply put straight to use. The assets that we imported were not built with the intention of running on HoloLens 2, nor a mobile device. They are heavy and require resources that are beyond what we can offer and, if we can, not reliably. In this course, we will take a hard look at our world builder project. Modify project settings best suited for our target hardware, optimize the materials and textures, remove unneeded mechanics or enable the user to toggle them, clean up our blueprints, learn some asset tips and tricks to assist us, and we'll end by profiling our project from the HoloLens on our desktop using unreal insights to assist us with our optimizing efforts. While we have gone through this project without thinking much of optimization and performance constraints, we must now do so at the end. This is not recommended for your projects. Make it routine to monitor your imported meshes and assets. Right, clean and organize code at the start, build, optimize materials and keep an eye on your lighting. Profile the project soon and often. Don't just wait until the end to think about these very important tasks. This will make the project more enjoyable and easier to handle moving forward.
