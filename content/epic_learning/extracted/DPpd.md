*This article discusses many questions that can come up when you set up the Gameplay Ability System (GAS) in your project. What is best practice is project dependent so this page presents things to consider.*

- [{'type': 'paragraph', 'content': 'Immediately: Servers and standalone clients can call GiveAbilityAndActivateOnce to grant and immediately activate the ability.'}]
- [{'type': 'paragraph', 'content': 'Via Class: Clients can call TryActivateAbilityByClass passing in an ability class. If the ASC owns an ability of that exact class (not subclass), that ability will attempt to activate. This is convenient when you know an exact ability that the player has, but less useful in more dynamic situations.'}]
- [{'type': 'paragraph', 'content': 'Via Tag: An ability can be configured with AssetTags, also known as DefaultAbilityTags. Clients can call TryActivateAbilityByTag with a set of tags. Any granted ability that has all of those tags as AssetTags will then attempt to activate. This is useful when your game design has a predetermined list of player verbs like “Jump” and “Light Melee Attack” and it varies at runtime which ability class is equipped on the player.'}]
- [{'type': 'paragraph', 'content': 'Via Handle: When you give an ability a unique handle is returned. You can then call TryActivateAbility and pass in that handle to specifically activate that ability. In networked projects, make sure the handle is replicated.'}]
- [{'type': 'paragraph', 'content': 'Via Input ID: If you grant abilities while providing an InputID and have also called BindAbilityActivationToInputComponent, then button presses mapped to those inputs will also activate abilities. Read the section "How does giving and triggering abilities via Input ID work?"\xa0 below for how to do this. This is convenient to save on boilerplate code in simple cases, but also inflexible due to using a fixed enum and not allowing you to add wrapping code.'}]
- [{'type': 'paragraph', 'content': 'Via Ability Trigger: Abilities can be configured to activate when their owning actor receives a specific Gameplay Tag or “Event” (tag and payload). This can be configured in the ability blueprint’s AbilityTriggers property. Abilities will respond to these triggers as long as they’ve been granted to an ASC and aren’t already activated. For more information about payloads when triggering via gameplay event, continue reading.'}]

- [{'type': 'paragraph', 'content': 'Reliable RPCs from the same actor will execute in the same order on the other end.
